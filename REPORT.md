Освоить базовые компоненты Compose, оформление через Modifier, локальное состояние и рекомпозицию на примере интерактивного профиля пользователя.

<a id="part1"></a>
## Программирование мобильных устройств — часть 1

### Компоненты и разметка

| Компонент | Назначение |
|:---|:---|
| `Avatar` | Круглая иконка пользователя в контейнере Box |
| `ProfileInfo` | Имя и фамилия, статус, подписчики |
| `ActionButtons` | Подписка и сброс, события через callback-параметры |
| `ProfileScreen` | Общая разметка и источник локального состояния |
| `User` | Модель данных профиля |

Использованы `Column`, `Row`, `Box`, `Text`, `Icon`, `Card`, `OutlinedTextField` и `HorizontalDivider`. Аватар имеет размер 120 dp, обрезку CircleShape и рамку 3 dp. Для трёх отдельных компонентов и полного экрана предусмотрены Preview-функции.

Существующее оформление сохранено. Для доступности содержимого при открытой клавиатуре добавлены системные отступы, вертикальная прокрутка и `imePadding`.

<a id="part2"></a>
## Программирование мобильных устройств — часть 2

### Состояние и интерактивность

| Состояние | Начальное значение | Изменение |
|:---|:---|:---|
| Имя | Сергей | Поле «Редактировать имя» |
| Статус | Студент СКФУ / группа | Поле «Редактировать статус» |
| Подписка | false | Кнопка подписки |
| Подписчики | 128 | +1 при подписке, -1 при отписке |
| Счётчик | 0 | Кнопка «+» |

Все значения хранятся в `ProfileScreen` через `remember` и наблюдаемые State-объекты. Актуальная модель для отображения создаётся через `initialUser.copy(...)`. Кнопка сброса восстанавливает имя и остальные состояния к начальным значениям.

Дочерние компоненты получают данные и обработчики событий параметрами. Это пример подъёма состояния к родительскому компоненту, а не полноценная архитектура MVVM. ViewModel не добавлена.

Изменение числа подписчиков реализовано. Дополнительные анимация подписки и переключатель светлой/тёмной темы не реализованы и не заявляются выполненными.

## Программирование мобильных устройств — контрольные вопросы

<details>
<summary>1. Что такое Jetpack Compose и в чём его отличие от XML-вёрстки?</summary>

Compose — инструментарий декларативного интерфейса Android. UI описывают Composable-функциями на Kotlin в зависимости от состояния. При традиционном подходе разметка находится в XML, а код взаимодействует с View. XML-подход продолжает поддерживаться; его наличие не означает, что проект неработоспособен.

</details>

<details>
<summary>2. Что такое @Composable-функция?</summary>

Функция с аннотацией `@Composable`, участвующая в описании интерфейса. Вызывается из Composable-контекста. В работе это `Avatar`, `ProfileInfo`, `ActionButtons` и `ProfileScreen`.

</details>

<details>
<summary>3. Что такое Modifier и приведите примеры его использования.</summary>

`Modifier` — цепочка элементов, задающих оформление, разметку и поведение компонента. В проекте используются `padding`, `size`, `fillMaxWidth`, `clip`, `border` и `verticalScroll`. Порядок имеет значение: `background(...).padding(...)` окрашивает также область внутренних отступов, а `padding(...).background(...)` оставляет внешние отступы вне фона.

</details>

<details>
<summary>4. Как управлять состоянием в Compose? Что такое remember?</summary>

Наблюдаемое значение можно создать через `mutableStateOf` и сохранить между рекомпозициями через `remember`. `remember` сам по себе не сохраняет состояние после пересоздания Activity. Для поддерживаемых сохраняемых данных используют `rememberSaveable`, для состояния уровня экрана также может применяться ViewModel.

</details>

<details>
<summary>5. Как работает рекомпозиция в Compose?</summary>

При изменении наблюдаемого состояния Compose планирует повторное выполнение затронутых частей композиции, читавших это состояние. Это не обязательная перерисовка всего экрана. Например, ввод имени изменяет State, и `ProfileInfo` получает обновлённое значение.

</details>

<details>
<summary>6. В чём разница между Column и Row?</summary>

`Column` размещает элементы вертикально, `Row` — горизонтально. В профиле Column объединяет блоки экрана, а Row размещает кнопки и элементы счётчика рядом. Для наложения элементов используют Box.

</details>

<details>
<summary>7. Как использовать TextField в Compose?</summary>

Для варианта с параметрами `value` и `onValueChange` значение хранится снаружи, а callback обновляет его при вводе. В этой работе используется `OutlinedTextField` из Material 3.

```kotlin
OutlinedTextField(
    value = nameText,
    onValueChange = { nameText = it },
    label = { Text("Редактировать имя") }
)
```

</details>

<details>
<summary>8. Что такое Divider и для чего он нужен?</summary>

Разделитель визуально отделяет блоки интерфейса тонкой линией. В текущем Material 3 проекте применяется `HorizontalDivider` между полями профиля и кнопками действий.

</details>

<details>
<summary>9. Для чего нужна аннотация @Preview?</summary>

Она позволяет показать Composable-компонент в предпросмотре Android Studio с подготовленными данными, без установки приложения на устройство. Preview не заменяет сборку, запуск и проверку пользовательских действий.

</details>

<details>
<summary>10. Как вынести повторяющийся код в отдельный компонент?</summary>

Создать отдельную Composable-функцию и передавать различающиеся данные, Modifier и обработчики событий через параметры. В работе `ProfileInfo` получает модель User, а `ActionButtons` — состояние подписки и callbacks. Так компоненты можно повторно использовать без копирования разметки.

</details>
